TLSH

TLSH（Trend Micro Locality Sensitive Hash）是一种相似性摘要：它把文件的字节分布压缩成固定长度的摘要，并用距离衡量两个摘要的差异。它适合寻找与已知样本相似的文件，但距离较小只是一条分析线索，不能单独证明文件恶意或属于同一个木马家族。

为什么需要相似性哈希​

SHA-256 等密码学哈希适合标识文件和验证完整性。文件只要发生很小的变化，SHA-256 通常就会完全不同，因此无法通过比较两个 SHA-256 的外观判断文件是否相似。

木马可能在保留大量代码的同时改变配置、资源或少量代码，产生多个 SHA-256 不同的样本。TLSH 试图从字节的局部组合和整体统计分布中保留相似性，让分析人员有机会找出这些近似样本。

对比项SHA-256TLSH
主要用途精确标识、完整性校验相似样本检索、聚类和分析
结果比较摘要一致可用于判断文件是否一致计算距离；距离越小，摘要越相近
安全属性密码学哈希不是密码学完整性校验，也不能证明文件一致

计算原理​

以官方实现常见的标准配置为例，TLSH 的计算可以理解为以下几步。具体实现还支持不同桶数和校验和长度，比较时应确认摘要格式和配置兼容。算法细节可参考 TLSH 原始论文和官方项目。

输入字节流
  ↓
5 字节滑动窗口逐字节移动
  ↓
从窗口中的字节组合提取特征，映射到桶并计数
  ↓
计算桶计数的四分位点，将每个桶量化为 2 位
  ↓
加入长度、四分位比例和校验和信息
  ↓
生成 TLSH 摘要 → 与其他摘要计算距离

1. 滑动窗口和桶计数​

窗口每次覆盖 5 个连续字节，向前移动一个字节。算法从每个窗口选取若干组 3 字节组合，通过映射函数将它们映射到桶，对相应桶的计数加一。标准配置使用 128 个有效桶。桶统计的是局部字节组合的出现情况，不保留文件完整内容或每个特征的原始位置。

例如，一个窗口中的多组字节特征可能映射到不同桶；随着窗口扫描整个文件，各桶累计出一组反映字节分布的计数。桶相同并不意味着原始字节组合一定相同，映射可能发生碰撞。

2. 四分位数和摘要正文​

算法对桶计数计算三个四分位点 Q1、Q2、Q3，再根据每个桶的计数落在这些分界点的哪个区间，将其编码为 0、1、2 或 3，也就是每个桶用 2 位表示。这样保留下来的是各桶相对于整体分布的量化信息，而不是原始计数。

标准配置下，128 个桶编码为 32 字节的摘要正文。量化使摘要对部分变化具有一定容忍度，同时也会丢失细节：不同文件可能得到相同或相近的摘要。

3. 摘要头部​

摘要还包含校验和、文件长度的压缩表示，以及 Q1/Q3、Q2/Q3 的量化比例，用于补充整体信息。标准配置的摘要数据为 35 字节：3 字节头部加 32 字节正文。常见文本表示为 T1 版本前缀加 70 个十六进制字符；旧格式可能没有 T1 前缀。官方项目说明了格式及兼容性。

这里的校验和只是距离计算的一部分，不是用于认证文件来源或完整性的密码学签名。

4. 计算距离​

比较两个有效摘要时，TLSH 根据摘要头部和正文的差异计算距离。默认比较会考虑长度差异；官方接口也提供忽略长度项的比较方式。距离越小，表示摘要越接近；它不是百分比，也没有通用于所有文件类型和场景的固定恶意阈值。距离为 0 也不能证明两个文件字节完全相同，应通过文件内容或密码学哈希进一步确认。

例如，待分析文件与已知样本的距离较小，可以把它列为优先分析对象；距离较大也不能排除相同功能或关联，因为打包、加密、重编译或大幅结构变化都可能改变字节分布。

在木马检测中能做什么​

  1. 发现潜在变种：将新文件与已确认木马样本的 TLSH 库比较，找出摘要距离较小的候选项，即使它们的 SHA-256 不同。
  2. 样本聚类和去重辅助：对大量样本计算距离，归并可能相近的样本，帮助安排分析优先级。相似性聚类不是精确去重，仍需保留各样本的 SHA-256。
  3. 关联历史情报：对候选近邻查看来源、采集时间、家族标签和关联基础设施，辅助发现可能相关的攻击活动。标签本身也需要核实。
  4. 补充检测线索：把相似性结果与签名、文件结构、静态代码、进程行为、网络通信等证据结合，再判断是否告警或进一步分析。

例如，新发现一个可执行文件，其 SHA-256 与库中已知木马不同，但 TLSH 与某个已确认样本距离较小。合理的结论是“值得检查是否存在代码或资源上的关联”，接下来可以比较 PE 结构、可疑字符串、导入函数及运行行为；仅凭距离不能断定它就是该家族，也不能断定它一定恶意。

如何设置距离阈值​

阈值需要用自己的数据验证，而不是直接把某个数字当成通用标准：

  • 按文件类型、大小范围、是否打包等条件构造评估集，包含已知相关样本和无关样本，也要包含常见良性软件。
  • 用经核实的标签比较不同阈值下的误报和漏报，结合人工复核成本选择候选阈值。
  • 在实际部署中持续观察效果；不同家族、编译方式和数据来源可能需要不同策略。
  • 记录 TLSH 版本、摘要配置、是否计入长度，以及样本来源，确保结果可以复现。

距离大小只能反映摘要上的差异，不能直接解释为“共享了多少百分比的代码”。

使用示例​

官方 Python 扩展提供 tlsh.hash 和 tlsh.diff。安装及平台支持以官方项目的安装说明为准；下面只读取文件计算摘要，不执行文件：

from pathlib import Path
import hashlib
import tlsh


def fingerprints(path: str) -> tuple[str, str]:
    data = Path(path).read_bytes()
    sha256 = hashlib.sha256(data).hexdigest()
    fuzzy = tlsh.hash(data)
    if not fuzzy or fuzzy == "TNULL":
        raise ValueError(f"无法计算有效 TLSH：{path}（文件可能过短或内容复杂度不足）")
    return sha256, fuzzy


sha_a, tlsh_a = fingerprints("sample_a.bin")
sha_b, tlsh_b = fingerprints("sample_b.bin")
print("SHA-256 A:", sha_a)
print("SHA-256 B:", sha_b)
print("TLSH A:", tlsh_a)
print("TLSH B:", tlsh_b)
print("TLSH 距离:", tlsh.diff(tlsh_a, tlsh_b))

该示例一次性读取整个文件，适合演示；处理大文件或批量样本时，可使用官方接口的增量计算能力。实际处理未知样本时，应遵守所在环境的样本管理和隔离要求。

局限与注意事项​

  • 输入要求：官方实现的默认模式通常要求至少 50 字节，且内容需要有足够复杂度；重复内容过多也可能无法生成摘要。不同版本、配置或接口的最小长度要求可能不同，不能计算不代表文件安全。
  • 相似不等于恶意：共用编译器、运行库、安装器、壳或其他公共组件的良性与恶意文件可能相似，导致误报。
  • 不相似不等于无关：加密、压缩、打包、重编译及其他大幅修改可能使相关样本的距离变大；TLSH 不能理解程序语义，也不能直接判断行为是否相同。
  • 整体文件与载荷要区分：外层 Loader 的摘要与解包后的载荷摘要描述不同对象；可以分别计算和记录，不能把二者当成同一文件。
  • 对抗风险：相似性摘要可受到针对性修改的影响，不宜作为唯一防线。相关研究可参阅 Using Randomization to Attack Similarity Digests。
  • 样本来源与隐私：将文件或摘要提交第三方平台前，应确认数据敏感性、平台权限和使用规则。
