先说结论：公开样本显示，银狐（Silver Fox）并不是只依赖单一提权手法。

如果把近两年公开分析里出现过的行为串起来看，它更常见的思路是沿着一条“逐层抬高权限”的链路向上走，而不是一上来就直接利用某个本地提权漏洞拿到最高权限。

可以把这条链路大致理解为：

```text
普通用户
   ↓
UAC Bypass
   ↓
管理员
   ↓
启用 SeDebugPrivilege
   ↓
窃取高权限 Token
   ↓
SYSTEM
   ↓
冒充 TrustedInstaller
   ↓
修改受保护组件
   ↓
(部分新样本)
BYOVD
   ↓
Kernel
```

也就是说，银狐主流样本更像是在**滥用 Windows 自身的权限与令牌机制**，而不是主要依赖某个著名的本地提权 CVE。

## 特征

很多人在看木马分析时，容易把“提权”理解成一个瞬间完成的动作，好像样本一运行就直接从普通用户跳到 SYSTEM。

但从银狐相关公开分析来看，它更像是把权限抬升拆成了多个连续阶段：

- 先想办法绕过 UAC，拿到高完整性的管理员权限。
- 再启用 `SeDebugPrivilege`，让自己更容易打开和操作高权限进程。
- 然后窃取或复制高权限进程的访问令牌，进入 `NT AUTHORITY\SYSTEM` 上下文。
- 在此基础上，进一步冒充 `TrustedInstaller`，去修改普通管理员甚至 SYSTEM 都不方便直接改的受保护组件。
- 部分更新的 ValleyRAT / Winos 4.0 样本，还会继续往上走，加载存在漏洞的签名驱动，把权限推进到内核态。

这也是为什么讨论银狐提权时，不能只盯着一个动作看，而要看它是不是形成了完整的权限抬升链。

## 阶段

### UAC Bypass

在近期公开分析中，研究人员发现 ValleyRAT / Winos 4.0 相关样本中出现了与 UAC 绕过有关的函数和逻辑，例如：

```text
RunUAC()
CheckAdminPrivileges()
BypassUACViaDebugObject()
```

这类逻辑的核心目标不是“提到 SYSTEM”，而是先把当前进程从普通用户或中完整性管理员，抬到**高完整性的管理员上下文**。

公开报告提到，其实现思路中出现过：

```text
RPC AppInfo
+
Debug Object Hijacking
+
computerdefaults.exe
```

从防守视角理解，这一阶段的关键点在于：

- 样本先判断自己当前是不是已经具备管理员权限。
- 如果没有，就尝试借助 Windows 的 UAC 机制和可被滥用的自动提权组件，绕过正常的用户确认提示。
- 一旦成功，后续进程就会以更高完整性运行，为后面的令牌操作、进程访问和持久化修改打基础。

#### 可见信号

在主机日志或 EDR 遥测里，这一阶段经常会让一些原本就比较敏感的系统组件异常出现，例如：

```text
computerdefaults.exe
fodhelper.exe
sdclt.exe
eventvwr.exe
```

这些文件名本身并不等于恶意，但如果它们的启动链、父进程、命令行、时序关系明显异常，就很值得重点看。

### SeDebugPrivilege

拿到管理员权限以后，银狐常见的下一步并不是立刻注入所有系统进程，而是先把关键权限打开。

公开分析中提到它会围绕下面这条链路操作：

```text
OpenProcessToken
↓
LookupPrivilegeValue
↓
AdjustTokenPrivileges
```

目标是启用：

```text
SeDebugPrivilege
```

#### 关键作用

`SeDebugPrivilege` 可以理解为一种高危调试权限。它本来是给调试器、系统诊断工具、安全产品和故障排查工具使用的，但在恶意样本里很常见，因为它会让进程更容易：

- 打开高权限进程。
- 获取更强的目标进程句柄。
- 读取或操作其他进程的内存与令牌。
- 为后续的 Token Theft、注入、转储或线程控制创造条件。

换句话说，银狐在这一层做的事，不是直接“提权成功”，而是先为后面的高权限进程访问铺路。

#### 检测视角

单独看到某个进程启用了 `SeDebugPrivilege`，并不能直接下结论说它就是木马，因为很多安全工具、调试器和运维组件也会这么做。

真正值得警惕的是它后面紧跟着出现了什么：

- 是否马上去打开 `winlogon.exe`、`lsass.exe`、`services.exe` 等敏感进程。
- 是否出现进程令牌复制、模拟登录用户、远程线程、跨进程读写内存等动作。
- 该进程本身的路径、签名、父进程、命令行是否合理。

如果一个陌生进程在临时目录、用户目录或办公软件子进程链下突然启用 `SeDebugPrivilege`，风险通常会明显上升。

### Token Theft

这是银狐样本里比较有代表性的提权动作。

公开分析指出，它会在启用 `SeDebugPrivilege` 之后，进一步对高权限进程做访问令牌操作，典型思路可以概括为：

```text
Enable SeDebugPrivilege
↓
OpenProcess(winlogon.exe)
↓
DuplicateTokenEx
↓
ImpersonateLoggedOnUser
```

最终进入：

```text
NT AUTHORITY\SYSTEM
```

上下文。

#### 本质

这一步更准确地说属于：

```text
MITRE ATT&CK T1134
Access Token Manipulation
```

它本质上不是“利用内核漏洞”，而是**滥用 Windows 的访问令牌机制**。

Windows 中，进程是否以某个身份运行，本质上依赖于它绑定的访问令牌。攻击者如果已经具备足够高的访问能力，就可能去复制高权限进程的令牌，再用复制出的令牌模拟该身份或创建新的高权限进程。

银狐在这里的关键，不是自己凭空生成一个 SYSTEM 身份，而是：

- 先用管理员权限和 `SeDebugPrivilege` 取得对敏感进程的访问能力。
- 再从高权限进程身上复制可用 Token。
- 最后利用这个 Token 进入 SYSTEM 上下文。

#### 目标选择

从防守角度看，`winlogon.exe` 是一个很典型的高权限目标，因为它通常运行在 SYSTEM 上下文中，而且对登录会话相关活动很敏感。

恶意样本盯上它，不代表只有它能被利用，而是它经常成为一类代表性目标：

- 权限足够高。
- 进程长期存在。
- 访问它本身就具有很强的异常性。

因此，如果在遥测里看到某个不应具备调试或安全管理职责的进程突然去强访问 `winlogon.exe`，再跟上 `DuplicateTokenEx`、模拟身份、创建新进程，这通常就是非常强的提权信号。

### TrustedInstaller

很多人在学 Windows 权限时，会以为 `SYSTEM` 已经是无条件的最高权限。但在很多具体运维与系统保护场景里：

```text
SYSTEM ≠ TrustedInstaller
```

Windows 中一些核心文件、受保护 DLL、计划任务组件和系统资源，真正的拥有者可能是：

```text
TrustedInstaller
```

这意味着即便恶意样本已经进入 SYSTEM，上层有些对象仍然不一定方便直接修改。

公开分析提到，银狐会在 SYSTEM 基础上进一步获取 `TrustedInstaller` Token，并进行模拟或继承，然后去修改一些受保护组件。

常被提到的例子包括：

```text
C:\Windows\System32\TimeBrokerClient.dll
```

以及与其相关的重命名、替换、旁加载等行为，例如分析里经常提到：

```text
Rename TimeBrokerClient.dll
BrokerClientCallback.dll
```

#### 深入原因

因为从攻击者角度看，进入 SYSTEM 只是“已经足够强”，但不代表“所有受保护文件都能随意改”。

如果样本的目标是：

- 替换受保护 DLL。
- 修改系统组件加载关系。
- 调整某些默认由 `TrustedInstaller` 拥有的资源。

那么继续往 `TrustedInstaller` 走就会更稳。

从检测角度，这一层的价值在于：**它说明样本并不满足于单纯获得高权限，而是想进一步控制系统受保护资源。**

### BYOVD

在较新的 ValleyRAT / Winos 4.0 相关公开报告中，已经能看到更高阶的一层：

```text
Bring Your Own Vulnerable Driver
```

也就是常说的：

```text
BYOVD
```

它的思路不是自己写一个未签名内核驱动，而是想办法加载一个**合法签名但存在已知漏洞的驱动**，再利用这个驱动在内核里执行高危操作。

公开分析中提到过的行为包括：

- 加载存在问题的签名驱动，例如 `wsftprm.sys`。
- 借助 `NtLoadDriver`、`RtlAdjustPrivilege` 等相关能力完成驱动加载。
- 在拿到 Ring0 之后，尝试关闭 EDR、绕过 PPL、隐藏进程或进一步削弱系统防护。

#### 风险

因为这意味着提权已经不再停留在用户态高权限，而是继续向内核态推进。

一旦样本真的走到这一步，防守难度会显著上升。原因包括：

- 某些用户态安全拦截会失效或被绕开。
- 攻击者可能直接干预安全产品驱动。
- 受保护进程、内核回调、进程可见性等边界会被进一步破坏。

不过需要注意的是，并不是每个银狐样本都会稳定走到这一层。更准确的说法是：**这是部分更新变种已经出现的补充型高权限手段。**

## 提权后的标准动作流

提权不是攻击者的最终目标。管理员、`SYSTEM`、`TrustedInstaller` 或内核权限的价值，在于解除后续动作的访问限制。真正需要研判的是：**新获得的权限马上被用来做了什么。**

从攻击链角度，可以把提权后的常见动作归纳为：

```text
权限确认与令牌固化
        ↓
安全产品与环境探测
        ↓
凭据、密钥与会话访问
        ↓
高权限持久化 / 白进程寄生
        ↓
横向移动与远程控制
        ↓
数据发现、收集与外传
        ↓
清理痕迹、恢复机制与破坏动作
```

这不是固定脚本。窃密型木马可能把“数据收集”提前；远控木马可能先建立持久化和 C2；破坏型攻击则可能先削弱安全产品，再集中执行加密或擦除。

### 权限确认与令牌固化

攻击者首先需要确认新上下文是否真的可用，包括当前身份、完整性级别、已启用特权、会话以及能否访问预定对象。随后可能复制令牌、创建高权限子进程，或把权限传递给一个更稳定的长期宿主。

防守侧应关注：

- 提权事件后短时间内出现令牌复制、身份模拟或高完整性子进程。
- 用户目录、临时目录中的进程突然派生 `SYSTEM` 上下文进程。
- 新进程继承了与其业务职责不相符的敏感特权。

### 安全产品与环境探测

获得高权限后，攻击者通常会枚举安全软件、驱动、服务、进程、策略与网络出口，判断哪些动作容易被拦截。随后可能选择避开、停用、篡改策略或切断安全产品与云端的通信。

这一步的目的不是“多做一次主机信息收集”，而是为后面的凭据访问、注入和持久化清场。可与 [安全产品致盲](./安全产品致盲.md) 联动分析。

### 凭据与敏感材料访问

高权限经常被用于接触普通用户读不到的材料，例如登录会话、浏览器数据、系统密钥、服务账户配置、远程连接凭据和其他进程中的认证状态。

应重点关联：

- 对认证相关进程的异常句柄访问或内存读取。
- 对凭据存储、密钥目录、浏览器配置和远程工具配置的批量读取。
- 短时间内出现压缩、编码、暂存或向外部地址传输。

“成功打开敏感进程”只能说明具备访问条件；是否真的取得凭据，还需要内存读取、转储文件、工具痕迹或后续登录事件等证据支撑。

### 高权限持久化

攻击者会尽量让后门在重启、用户注销或原进程退出后仍能恢复，常见落点包括高权限服务、计划任务、登录链路、系统组件加载关系、WMI 订阅以及受信任软件的插件机制。

提权后的持久化通常比用户态自启动更危险，因为它可能：

- 早于普通用户登录启动。
- 以 `SYSTEM` 身份运行。
- 修改普通管理员不易恢复的受保护资源。
- 借合法系统宿主降低进程外观异常。

### 进程注入与白进程寄生

把载荷转移到长期驻留、允许联网或信誉较高的进程，可以隐藏原始加载器并继承目标上下文。这里既包括真正的跨进程[注入](./注入.md)，也包括 [白加黑利用](./白加黑利用.md)、插件加载和 [MSI CustomAction](./CustomAction.md) 等进程内寄生。

研判时应区分：

```text
权限提升：解决“能不能访问”
注入或寄生：解决“代码在哪里运行”
持久化：解决“以后还能不能回来”
```

三者经常连续出现，但不是同一个技术点。

### 横向移动与远程控制

本机高权限还可被用来访问管理共享、远程服务、计划任务、远程管理接口或企业运维通道。攻击者真正需要的是可复用的账户、令牌和网络可达性，而不是单纯让本机显示为 `SYSTEM`。

检测时可把本机提权时间作为锚点，向后关联：

- 对内网地址的异常认证和端口扫描。
- 新出现的远程服务、远程任务或管理会话。
- 同一账户在多台主机短时间内登录。
- 高权限进程访问共享路径并向其他主机写入文件。

### 数据收集与外传

在权限和驻留都稳定后，攻击者可能枚举文档、即时通信数据、浏览器资料、数据库与业务目录，然后在本地暂存、压缩、分卷或加密，再通过已有 C2、云存储或其他网络通道外传。

高价值组合信号是：

```text
高权限身份
+
跨用户目录或敏感业务目录的批量读取
+
临时归档文件增长
+
异常公网连接
```

### 痕迹清理、恢复与破坏

最后一类动作包括清理临时文件、改变日志与审计配置、删除一次性任务、恢复被替换的表面文件，以及设置看门狗或备用持久化，确保主模块被终止后还能重新拉起。破坏型攻击还可能在这一阶段停止业务、删除恢复能力、加密数据或擦除系统。

“日志减少”本身不能证明日志被清除。需要同时检查审计策略变化、日志服务状态、事件时间断层、转发端缺口，以及本地与中心日志是否相互矛盾。

### 抽象案例

假设一个来自用户目录的进程绕过 UAC 后启用了调试特权，接着复制高权限令牌。若后续只看到它创建了一个高完整性命令解释器，这仍只是“权限已被使用”的证据；如果随后又出现：

1. 枚举安全软件与敏感服务。
2. 打开认证相关进程并读取内存。
3. 创建高权限计划任务。
4. 把载荷转移到长期驻留的合法宿主。
5. 访问多个用户目录并连接外部地址。

那么完整意图已经从“提权尝试”升级为“凭据访问 + 持久化 + 防御规避 + 数据外传”。响应范围也不应只停留在删除最初的可执行文件，而要围绕身份、持久化、横向活动和数据影响全面排查。

### 调查顺序

以提权成功时刻为中心建立时间线，通常按下面的顺序最有效：

1. 确认提权前后的进程、用户、会话、令牌和完整性级别。
2. 查看随后五分钟内的敏感进程访问、安全产品操作和持久化写入。
3. 扩展到网络连接、认证事件、共享访问和远程执行。
4. 检查跨用户数据读取、归档文件、云存储和外传迹象。
5. 回看提权前的初始入口，并向后确认所有备用驻留点。

这样做的核心是把“拿到什么权限”转化为“权限解锁了哪些后续行为”。

## 检测

如果你在做 EDR Hunting、Sysmon 检测或 Windows 主机排查，比起只盯某一个单独 API，更有价值的是看下面这条组合行为是否完整出现：

```text
AdjustTokenPrivileges
    ↓
SeDebugPrivilege Enabled
    ↓
OpenProcess(winlogon.exe)
    ↓
DuplicateTokenEx
    ↓
CreateProcessAsUser / Impersonation
```

这通常意味着：

```text
管理员
→ SYSTEM
```

的 Token Theft 很可能正在发生。

如果在这之后，又继续出现：

```text
NtLoadDriver
```

或者主机上突然加载来源异常、用途异常的：

```text
*.sys
```

那就要考虑它是不是已经从：

```text
SYSTEM
→ Kernel
```

继续推进了。

## 归类

从目前公开样本特征来看，银狐更典型的提权路线不是：

```text
利用某个 Windows 本地提权 CVE
↓
直接拿到 SYSTEM
```

而更像是：

```text
UAC Bypass
→ 管理员
→ SeDebugPrivilege
→ Winlogon Token Theft
→ SYSTEM
→ TrustedInstaller
```

以及在部分更新变种中继续补上：

```text
BYOVD
→ Kernel Privilege
```

这条链的意义在于，它提醒我们：很多恶意样本并不需要真正在本机上打穿一个 0day 或 LPE 漏洞，也能通过对系统内建权限机制、令牌机制和驱动加载机制的滥用，逐层把自己的权限堆上去。

## 排查

如果是从蓝队或应急响应角度看，下面这些信号比较值得组合分析：

- 与 UAC 绕过相关的系统组件异常启动，尤其是 `computerdefaults.exe`、`fodhelper.exe`、`sdclt.exe`、`eventvwr.exe` 等。
- 某个原本不应具备调试能力的进程突然启用 `SeDebugPrivilege`。
- 对 `winlogon.exe`、`lsass.exe`、`services.exe` 等敏感进程出现异常强访问。
- 进程令牌复制、模拟用户、以新令牌创建进程等行为。
- `TrustedInstaller` 上下文被异常拉起，或者受保护 DLL、系统组件发生可疑重命名与替换。
- 主机上加载异常驱动，特别是和 `NtLoadDriver`、签名驱动滥用、EDR 关闭动作接近出现的情况。

真正高价值的不是某一个点，而是这些点能不能拼成完整链路。

## 小结

银狐木马的提权思路，可以概括为一句话：

它并不总是依赖某个本地提权漏洞，而是更擅长把 Windows 现有的权限提升路径、令牌操作能力和受保护组件访问链路串起来，逐层把权限从普通用户推到管理员、SYSTEM、TrustedInstaller，甚至在部分新变种里继续推到内核态。

所以如果只把它理解成“某个 UAC 绕过样本”，或者只把它理解成“会偷 SYSTEM Token 的木马”，都还不够完整。

更准确的理解应该是：

```text
银狐常见提权路线
=
UAC Bypass
→ SeDebugPrivilege
→ Access Token Manipulation
→ TrustedInstaller Impersonation
→ (部分样本) BYOVD / Kernel
```
